# 숙박 상품 통합 연동

## 무엇을 하는가

여러 숙박 공급사의 서로 다른 API 를 하나의 표준 모델로 통합한다. 공급사의
숙소 목록을 받아 내부 식별자로 매핑해 두고, 고객이 날짜와 인원으로 검색하면
공급사에 병렬로 재고·요금을 물어 정규화한 뒤 하나의 결과로 합쳐 돌려준다.
공급사 하나가 실패해도 나머지 결과로 응답한다.

## 오픈 질문

| # | 질문 | 상태 |
|---|---|---|
| Q1 | 요금을 표준 모델에서 어떻게 표현할지 (기준값, 통화, 최소 단위, 조건) | 논의 중 — 세금 포함 총액 기준, `Money`, `RateConditions` 방향. 미확정. 막고 있는 구현: 검색 흐름 |
| Q2 | 날짜·숙박 구간을 어떻게 표현할지 | 미착수. 막고 있는 구현: 검색 흐름 |
| Q4 | 판매 조건(조식 포함 여부 등)을 어느 계층에 둘지 | 미착수 |
| Q5 | 새 공급사를 붙여도 표준 모델이 안 바뀌는 구조 (어댑터) | 논의 중 — 경계는 목록 조회·재고 조회 두 인터페이스로 나누고, 공급사마다 한 클래스가 둘을 묶은 인터페이스로 함께 구현한다(합의). 어댑터가 어디까지 하는지, 목록 조회 반환 타입, 공급사 등록 방식은 미정. ADR 은 나머지와 함께. 막고 있는 구현: 공급사 호출(목록 동기화·검색) |
| Q17 | 무엇을 어긋남으로 볼지(이름 표기 차이 등), 어떤 종류로 나눠 얼마나 어떤 형태로 남길지 | 미착수. Q18 모니터링 설계에서 함께 정함. 매핑에 없는 객실 타입의 누락도 함께 분류 (ADR-0014·0015) |
| Q18 | 연동 지표·모니터링을 어떻게 설계할지 (공급사별 성공률·응답 지연·타임아웃 비율, 어긋남·누락 포함) | 미착수 |
| Q19 | 운영자가 설정하는 숙소 목록 갱신 주기에 허용 범위(최소 간격)를 둘지 | 미착수 (ADR-0016 에서 생김) |
| Q23 | 동시 검색 요청을 어디서 얼마나 제한할지, DB 커넥션 풀·WebClient 커넥션 풀 크기와 공급사 동시 호출 수를 어떻게 맞출지, 검색 한 건 전체의 최대 시간을 어디서 정할지 | 미착수 (ADR-0021 에서 생김) |
| Q25 | 응답의 공급사 상태를 성공·실패 두 값으로 둘지, 규약 위반으로 항목이 빠져 결과가 줄어든 상태를 따로 드러낼지 | 미착수 (ADR-0027 에서 생김) |

## 결정 로그

| 결정 | ADR |
|---|---|
| 구현 언어 | ADR-0002 |
| Mock 공급사 모듈 분리 | ADR-0005 |
| 빌드 도구·프레임워크 버전 | ADR-0007 |
| JVM 툴체인 25 (ADR-0007 의 JVM 타깃 대체) | ADR-0022 |
| 공급사 호출 흐름을 Reactor 로 직접 다룸 | ADR-0009 |
| 같은 숙소를 병합해도 내부 식별자 유지 | ADR-0010 |
| 내부 식별자를 무작위 UUID 로 발급해 저장 | ADR-0011 |
| 응답의 숙소·객실 타입 정적 정보는 숙소 목록 기준으로 저장해 사용 | ADR-0012 |
| 숙소 목록은 앱 기동 시와 일정 주기마다 받아옴 | ADR-0013 |
| 목록 어긋남은 검색에서 감지하고 교정은 동기화 주기에 맡김 | ADR-0014 |
| 매핑에 없는 객실 타입은 응답에서 빼고 뺀 사실을 남김 | ADR-0015 |
| 숙소 목록 갱신 주기는 기본 하루 한 번, 설정으로 변경 가능 | ADR-0016 |
| 매핑은 서버형 관계형 DB 에 저장 (Q20) | ADR-0017 |
| 매핑을 저장할 DB 로 PostgreSQL | ADR-0018 |
| 공급사 첫 숙소 목록 실패에는 별도 장치 없음, 재시작·주기 설정으로 회복 (나중에 다시 볼 수 있음) | ADR-0019 |
| 서버는 Spring MVC, 공급사 호출만 WebClient (Q12) | ADR-0020 |
| 검색 요청은 가상 스레드에서 공급사 응답을 `block` 으로 기다림 (Q22) | ADR-0021 |
| 연박 예약 가능 객실 수는 날짜별 잔여 수의 최솟값 (Q3, 더 고민해 볼 지점으로 남김) | ADR-0023 |
| 규약과 다른 공급사 응답은 세 가지 질문(응답을 읽을 수 있나 / 출력 계산에 쓰이나 / 값을 하나로 정할 수 있나)으로 공급사 실패·무시·항목 제외를 가름 (Q24, ADR-0024·0025 대체) | ADR-0027 |
| 공급사 응답 DTO 는 스펙 필드를 모두 받기만 함. 모르는 필드 무시는 DTO 에 명시, 빠진 필드·null 판정은 내부 로직, 필드 이름은 응답 예시대로 (Q6) | ADR-0030 |
| 예약 불가 상품도 응답에 예약 가능 객실 수 0 으로 노출 (Q7) | ADR-0026 |
