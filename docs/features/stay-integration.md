# 숙박 상품 통합 연동

## 무엇을 하는가

여러 숙박 공급사의 서로 다른 API 를 하나의 표준 모델로 통합한다. 공급사의
숙소 목록을 받아 내부 식별자로 매핑해 두고, 고객이 날짜와 인원으로 검색하면
공급사에 병렬로 재고·요금을 물어 정규화한 뒤 하나의 결과로 합쳐 돌려준다.
공급사 하나가 실패해도 나머지 결과로 응답한다.

## 오픈 질문

| # | 질문 | 상태 |
|---|---|---|
| Q17 | 무엇을 어긋남으로 볼지(이름 표기 차이 등), 어떤 종류로 나눠 얼마나 어떤 형태로 남길지 | 미착수. Q18 모니터링 설계에서 함께 정함. 매핑에 없는 객실 타입의 누락도 함께 분류 (ADR-0014·0015) |
| Q18 | 연동 지표·모니터링을 어떻게 설계할지 (공급사별 성공률·응답 지연·타임아웃 비율, 어긋남·누락 포함) | 미착수 |
| Q19 | 운영자가 설정하는 숙소 목록 갱신 주기에 허용 범위(최소 간격)를 둘지 | 미착수 (ADR-0016 에서 생김) |

| 매핑을 저장할 DB 로 PostgreSQL | ADR-0018 |
| 공급사 첫 숙소 목록 실패에는 별도 장치 없음, 재시작·주기 설정으로 회복 (나중에 다시 볼 수 있음) | ADR-0019 |

| 스펙과 다른 공급사 응답은 세 가지 질문(응답을 읽을 수 있나 / 출력 계산에 쓰이나 / 값을 하나로 정할 수 있나)으로 공급사 실패·무시·항목 제외를 가름 (Q24, ADR-0024·0025 대체) | ADR-0027 |
| 공급사 응답 DTO 는 스펙 필드를 모두 받기만 함. 모르는 필드 무시는 DTO 에 명시, 빠진 필드·null 판정은 내부 로직, 필드 이름은 응답 예시대로 (Q6) | ADR-0030 |
| 공급사 어댑터는 목록 조회·재고 조회 두 경계로 나누고 공급사마다 한 클래스가 구현. 공급사 차이는 어댑터, 공통 판정 규칙은 공통 로직. 목록 조회도 `Mono`, 인터페이스 목록으로 주입 (Q5) | ADR-0031 |
| 매핑 저장·조회는 Spring JDBC 의 `JdbcClient` | ADR-0032 |
| 스키마 변경은 Flyway 스크립트로 | ADR-0033 |
| 내부 식별자 컬럼은 `uuid` 타입 (ADR-0018 이 미룬 것) | ADR-0034 |
| 로컬은 Docker Compose, 테스트는 Testcontainers | ADR-0035 |
| 매핑 테이블 둘, 내부 식별자(`uuid`)를 키로. 객실 타입은 내부 숙소 식별자로 숙소를 가리킴 | ADR-0036 |
| 목록에서 사라진 숙소·객실 타입은 매핑을 남기고 `missing_since` 표시 후 검색에서 제외. 값을 정할 수 없어 제외한 항목도 같게 본다 | ADR-0037 |
| 기동 시 동기화는 앱 기동을 막지 않음, 공급사 주소·키는 설정 파일의 공급사별 묶음, 트랜잭션은 공급사 단위 | ADR-0038 |
| 목록 조회 타임아웃은 공급사별 설정, 뺀 항목은 결과값과 로그로만 남김, 테스트는 테이블을 비워 되돌림 | ADR-0039 |
| 예약 불가 상품도 응답에 예약 가능 객실 수 0 으로 노출 (Q7) | ADR-0026 |
| 목록을 담는 필드가 없는 응답은 공급사 실패, 객실 타입이 없는 숙소는 제외. 값 검증은 담는 객체의 생성자에 둔다 | ADR-0041 |
| 요금은 세금 포함 기간 전체 총액 하나. 금액과 통화를 한 값 객체로 묶고, 1박 얼마로 보여줄지는 보여주는 쪽이 계산 (Q1) | ADR-0042 |
| 숙박 구간은 체크인·체크아웃 두 날짜의 값 객체. 날짜 목록은 그 객체가 만들고 체크아웃일은 넣지 않는다 (Q2) | ADR-0043 |
| 판매 조건은 별도 값 객체로 묶고 요금이 그것을 가진다. 층은 금액·조건·요금 셋까지 (Q4) | ADR-0044 |
| 재고·요금 호출을 50개 이하 묶음으로 나누고, 동시 실행 수와 검색 전체 시간 한계를 둔다. 풀 크기는 기본값 (Q23) | ADR-0045 |
| 검색 응답에 공급사 상태(성공·실패)와 내보낸 건수·스펙 때문에 뺀 건수를 싣는다. 매핑에 없어 뺀 것은 세지 않는다 (Q25) | ADR-0046 |
