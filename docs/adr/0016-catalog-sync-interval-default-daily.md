# 0016. 숙소 목록 갱신 주기는 기본 하루 한 번으로 두고 설정으로 바꿀 수 있게 결정

## Context

숙소 목록은 앱 기동 시와 일정 주기마다 받아온다([ADR-0013](0013-catalog-sync-on-startup-and-interval.md)).
주기 사이에는 옛 이름, 최대 수용 인원 증가 시 모순, 새 객실 타입 누락이 남는다
([ADR-0012](0012-static-info-from-catalog.md), [ADR-0015](0015-exclude-unmapped-room-types.md)).
어긋남은 검색에서 감지해 남기므로 나중에 주기를 조정할 근거가 되지만, 구현 전이라 아직 관측값은 없다
([ADR-0014](0014-detect-drift-in-search-correct-in-sync.md)).

이 저장소의 공급사 숙소 목록 API 는 전체 목록만 준다. 공개 문서를 조사한 해외 공급사들은 변경분이든
전체든 하루 한 번을 기준으로 안내하고, 그중 일부는 변경분만 받는 조회를 따로 둔다
([조사 기록](../research/catalog-sync-interval.md)).

## Options

- **(가) 하루 한 번으로 고정** — 조사한 공급사들의 안내와 같아 근거가 분명하고, 전체 목록을 받아도
  하루 한 번이라 부담이 작다. 대신 한계가 최대 하루 이어지고, 값을 바꾸려면 코드를 고쳐야 한다.
- **(나) 몇 시간마다로 고정** — 한계가 이어지는 시간이 짧다. 대신 자주 바뀌지 않는 전체 목록을 하루에
  여러 번 받게 되고, 조사한 안내보다 촘촘하게 둘 근거가 없다.
- **(다) 기본값은 하루 한 번, 운영자가 설정으로 바꿀 수 있게 둔다** ← AI 추천 — 기본값의 근거는 (가) 와 같다.
  어긋남 관측으로 특정 공급사의 변경이 잦다고 보이면 코드 수정 없이 줄일 수 있고, 목록 변경 반영을 확인할
  때도 짧게 바꿔 볼 수 있다. 대신 설정값이 하나 늘고, 너무 짧게 설정하면 공급사에 부담을 줄 수 있다.

## Decision

**(다)** 를 택한다. 숙소 목록 갱신 주기의 기본값은 하루 한 번이고, 운영자가 설정으로 바꿀 수 있다.

## Consequences

**얻는 것**
- 주기 값에 외부 근거가 있다
- 관측한 어긋남에 따라 코드 수정 없이 주기를 조정할 수 있다

**잃는 것**
- 기본값에서는 목록 갱신 전의 한계가 최대 하루 이어진다
- 조사한 곳 중 일부의 하루 한 번은 변경분만 받는 방식을 전제로 한다. 이 저장소의 공급사는 전체 목록만 주므로,
  공급사의 숙소가 아주 많아지면 하루 한 번 전체 조회도 무거울 수 있다
- 공급사 호출 한도 오류가 스펙에 있어, 주기를 짧게 하면 부딪칠 수 있다

**넘기는 것**
- 설정한 주기에 허용 범위(최소 간격)를 둘지 (Q19)

**스펙 제약이 바뀌면 다시 볼 것**
- 공급사가 변경분 조회를 제공하면 변경분은 매일, 전체는 드물게 받는 방식이 맞을 수 있다
- 공급사가 변경 알림을 제공하면, 조사한 국내 연동 플랫폼처럼 알림을 받고 해당 식별자만 다시 조회하는
  방식이 맞을 수 있다 (ADR-0012 의 범위 밖 확장과 같은 방향)

## Discussion

- **AI 주장과 근거** — 처음에는 Expedia 와 Hotelbeds 두 곳의 원문 안내만으로 기본값 하루 한 번을 권했다
- **반박** — 사용자는 (다) 에 동의하면서, 더 조사할 업체가 없었는지, 국내 업체도 보라고 했다
- **검증 결과** — Agoda, ETG, 국내 연동 플랫폼 두 곳을 더 조사했다. 해외 네 곳 모두 하루 한 번이 기준이었고, 그중
  두 곳은 변경분만 받는 방식을 따로 두었다. 국내 한 곳은 주기 대신 웹훅으로 변경 사실만 알리고 받는 쪽이 다시
  조회하게 했다. 결정은 그대로였고, 기본값의 근거가 두 곳에서 네 곳으로 늘었으며, "변경분이 없는 스펙이라 전체를
  매일 받는다"는 약점과 알림 방식이라는 확장 방향이 조사로 구체화됐다
- **그래서 어떻게 바뀌었나** — 결정은 바뀌지 않았다. 근거와 약점, 다시 볼 조건을 조사 결과로 보강했다

## Verification

아직 구현 전이다. 목록 동기화를 구현할 때 "설정한 주기가 적용되는지", "설정이 없으면 하루 한 번인지" 확인하는
테스트를 추가하고 이 절에 이름을 적는다.
