# 0014. 목록 어긋남은 검색에서 감지하고 교정은 동기화 주기에 맡기기로 결정

## Context

응답의 이름·최대 수용 인원은 숙소 목록에서 받아 저장한 값을 쓰고([ADR-0012](0012-static-info-from-catalog.md)),
숙소 목록은 앱 기동 시와 일정 주기마다 받아온다([ADR-0013](0013-catalog-sync-on-startup-and-interval.md)).
그 사이 공급사가 목록을 바꾸면 저장값과 실제가 어긋난다.

검색할 때 받는 재고·요금 응답에도 이름·최대 수용 인원·객실 타입 코드가 들어 있어서, 저장값과
다른지 그 자리에서 알 수 있다. 반면 숙소 목록 API 는 숙소 하나만 골라 받을 수 없어, 어긋남을
고치는 수단은 공급사 전체 목록을 다시 받는 것뿐이다.

## Options

- **(가) 아무것도 하지 않고 주기에만 맡긴다** — 가장 단순하다. 대신 어긋남이 얼마나 자주 생기는지
  모르므로 주기 값을 추측으로 정하게 된다.
- **(나) 어긋남을 보면 그 공급사의 목록 갱신을 앞당긴다** — 어긋난 상태가 짧아진다. 대신 숙소 하나가
  어긋나도 공급사 전체 목록을 다시 받고, 동시 검색이 같은 어긋남을 보면 갱신이 겹치므로 공급사마다
  앞당기는 간격을 제한해야 한다. 주기 갱신과 역할이 겹치는 장치가 검색 경로에 하나 더 생긴다.
- **(다) 검색에서 어긋남을 감지해 남기고, 교정은 동기화 주기에 맡긴다** ← AI 추천 — 감지는 이미 받은
  데이터로 하므로 추가 호출도 저장소 쓰기도 없다. 어긋남이 어느 공급사에서 얼마나 생기는지가 드러나
  주기 값의 근거가 되고, 연동 지표·모니터링 설계와 이어진다. 대신 어긋남을 알고도 다음 주기까지 둔다.

## Decision

**(다)** 를 택한다. 어긋남은 검색할 때 감지해 남기고, 교정은 목록 동기화 주기에서만 한다.
**고객 검색이 목록 갱신을 일으키지 않는다.**

## Consequences

**얻는 것**
- 검색 경로는 지연과 부분 실패를 다루는 역할만 갖고, 목록을 고치는 일은 동기화 경로 하나에 모인다
- 주기 값을 정할 때 추측이 아니라 관측한 어긋남을 근거로 쓸 수 있다

**잃는 것**
- 어긋남을 감지한 뒤에도 다음 주기까지 그대로 둔다. 이 중 매출에 닿는 것은 새 객실 타입이 응답에서
  빠지는 경우다. 이름 차이는 표시 문제이고, 최대 수용 인원 차이는 공급사가 이미 인원으로 거른 결과라
  예약에는 지장이 없다

**의존**
- 이름·최대 수용 인원의 어긋남을 감지하려면 공급사 응답을 받는 쪽이 그 필드를 받아야 한다 (Q6)

**넘기는 것**
- 새 객실 타입 누락을 다른 어긋남과 같은 무게로 볼지 (Q16)
- 무엇을 어긋남으로 볼지, 얼마나 어떤 형태로 남길지 (Q17)
- 주기 값과 그 근거, 운영자가 설정으로 바꿀 수 있게 둘지 (Q14)

**스펙 제약이 바뀌면 다시 볼 것**
- 공급사가 숙소 단위 목록 조회나 변경 알림을 제공하면, 교정 비용이 작아져 (나) 나 표적 갱신이 맞을 수 있다

## Discussion

- **AI 주장과 근거** — 처음에는 (다) 를 "어긋남을 기록만 한다"로 설명했다. 비용이 없고 주기 값의 근거가 된다는 이유였다
- **반박** — 사용자는 "알면서 다음 주기까지 두는데 기록만이 맞나" 망설였다. 맥락을 따로 받은 검토 AI 는
  결론은 같지만 이름이 틀렸다고 짚었다. 이 결정의 본질은 기록이냐 갱신이냐가 아니라, 고객 검색이 목록
  갱신을 일으켜도 되는가라는 것이다
- **검증 결과** — 이 스펙에서는 숙소 하나만 다시 받을 수 없어 교정 비용이 크고, (나) 의 간격 제한은 주기 갱신과
  겹치는 장치다. 어긋남 중 매출에 닿는 것은 새 객실 타입 누락 하나라 주기로 다스릴 수 있다
- **그래서 어떻게 바뀌었나** — 선택은 그대로 두고, 결정을 "감지와 교정의 분리"로 다시 세웠다. 새 객실 타입 누락은
  같은 자리에서 감지하되 무게를 따로 보도록 Q16 으로 넘겼다

## Verification

아직 구현 전이다. 검색을 구현할 때 "재고·요금 응답의 값이 저장값과 달라도 검색이 목록 갱신을 부르지
않는지", "어긋남이 남는지" 확인하는 테스트를 추가하고 이 절에 이름을 적는다.
