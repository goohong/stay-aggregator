# 0062. 목록과 재고 응답의 이름이 다르면 경고로 격리 기록에 남기기로 결정

## Context

숙소명과 객실 타입명은 숙소 목록 API 와 재고·요금 API 가 모두 준다. 응답에는 목록 쪽 저장값을 쓰기로 했다 ([ADR-0012](0012-static-info-from-catalog.md)).
그래서 재고 응답의 이름은 받지 않았다.

두 이름이 다르면 공급사가 이름을 바꿨는데 우리 목록이 아직 반영하지 못한 것일 수 있다.
[ADR-0014](0014-detect-drift-in-search-correct-in-sync.md) 가 "목록 어긋남은 검색에서 감지하고 교정은 동기화 주기에 맡긴다"고 했는데, 감지하는 곳이 아직 없었다 (Q17 의 남은 부분).

## Options

감지 여부
- **(가) 감지해서 경고로 남긴다** ← 채택 — 목록이 오래된(stale) 신호가 된다. 대신 재고 응답의 이름을 받아야 한다
- **(나) 하지 않는다** — 응답은 목록 이름을 쓰니 고객에게 영향이 없다. 대신 목록이 오래된 것을 알 단서가 없다

기록 자리
- **(ㄱ) 격리 기록 테이블에 "제외/경고" 구분을 더한다** ← 채택 — 그룹화·횟수·정리를 그대로 쓴다. 대신 테이블 이름(격리)과 경고가 조금 어긋난다
- **(ㄴ) 별도 테이블** — 뜻이 또렷하다. 대신 같은 그룹화·정리 코드가 두 벌이 된다

## Decision

- 재고 응답의 숙소명·객실 타입명을 **비교에만 쓰려고** 받는다. 응답에는 여전히 목록 이름을 쓴다 (ADR-0012)
- 두 이름이 다르면 **항목은 빼지 않고** 경고로 격리 기록에 남긴다. 문제가 된 값은 숙소명 또는 객실 타입명이다 ([ADR-0054](0054-exclusion-kind-by-value-only.md))
- 격리 기록에 **구분(제외/경고)** 을 더하고, 같은 문제로 그룹화하는 기준에 넣는다
- 이름 비교는 앞뒤 공백만 무시하고 그대로 비교한다. 표기를 정규화해 같다고 보는 것은 추정이라 하지 않는다

**이유**

- ADR-0014 가 정한 "검색에서 감지"의 자리가 이것이다
- 경고는 제외와 성격이 달라도 "같은 문제를 그룹화해 센다"는 필요가 같다

## Consequences

**얻는 것**
- 목록이 오래된 공급사·숙소를 기록으로 본다

**잃는 것**
- 재고 응답에서 받는 필드가 둘 는다
- 대소문자나 "Room" 같은 표기 차이도 경고가 된다. 정규화하지 않기로 했기 때문이다
- 격리 기록에 제외가 아닌 것이 섞여, 조회할 때 구분을 봐야 한다

## Verification

이름이 다르면 항목은 내보내고 경고를 남기는지, 응답 건수에 넣지 않는지
  → `AvailabilityNormalizerTest.재고 응답의 이름이 목록과 다르면 항목은 내보내고 경고를 남긴다`

앞뒤 공백만 무시하고 표기 차이는 경고하는지
  → `AvailabilityNormalizerTest.이름이 앞뒤 공백만 다르면 경고하지 않고 표기가 다르면 경고한다`

같은 값이라도 제외와 경고가 다른 문제로 그룹화되는지
  → `QuarantineIntegrationTest.같은 값이라도 제외와 경고는 다른 행이다`
