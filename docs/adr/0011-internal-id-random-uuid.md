# 0011. 내부 식별자를 무작위 UUID 로 발급해 저장

## Context

[ADR-0010](0010-keep-internal-id-on-merge.md) 에서 내부 식별자는 공급사 상품 하나를 가리키고,
한 번 발급하면 바꾸지 않기로 했다. 응답을 받는 쪽이 이 식별자를 들고 있다가 상세·예약 요청에
다시 쓴다. 같은 공급사 상품은 숙소 목록을 다시 받아와 매핑을 갱신해도 같은 식별자여야 한다.

어떤 방식으로 만들든 식별자는 매핑에 저장한다. 요청으로 들어온 식별자가 어느 공급사의 어느
코드인지 거꾸로 찾으려면 저장된 매핑이 필요하기 때문이다.

## Options

- **(가) 순서대로 번호를 발급** — 가장 단순하고 짧다. 대신 번호로 전체 숙소 수와 등록 순서가
  밖에서 보인다. 매핑 데이터를 잃고 다시 만들면 같은 상품이 다른 번호를 받을 수 있다.
- **(나) 무작위 UUID 를 발급** ← AI 추천 — 순서나 개수가 드러나지 않는다. 발급 로직을 바꿔도
  이미 저장된 식별자는 그대로다. 같은 공급사 상품을 서로 다른 내부 상품으로 둘 수도 있다.
  대신 매핑 데이터를 잃고 다시 만들면 새 값이 나온다.
- **(다) 공급사와 공급사 코드로 계산** (같은 입력이면 같은 값) — 매핑 데이터를 잃고 다시 만들어도
  같은 값이 나온다. 대신 계산 방식이 알려지면 식별자에서 공급사 코드를 거꾸로 찾을 수 있고,
  이를 막으려고 비밀 키를 섞으면 키를 관리해야 한다. 계산에 들어가는 공급사 이름 표기와 코드를
  바꿀 수 없고, 같은 공급사 상품을 둘로 둘 수 없다.

## Decision

**(나)** 를 택한다. 매핑을 새로 만들 때 무작위 UUID 를 발급해 저장하고, 다시 동기화할 때는
`(공급사, 공급사 코드)` 로 기존 행을 찾아 저장된 식별자를 그대로 쓴다.

**이유** — 식별자 발급 방식은 결과에 미치는 영향이 크지 않다고 보고 기본적인 방식을 택한다.

## Consequences

**얻는 것**
- 식별자에서 순서·개수·공급사 코드가 드러나지 않는다
- 발급 로직을 나중에 바꿔도 기존 식별자에 영향이 없다

**잃는 것**
- 매핑 데이터를 잃고 공급사 목록으로 처음부터 다시 만들면 식별자가 바뀐다.
  마이그레이션이나 백업 복구로는 저장된 값이 유지되므로, 이 위험은 매핑을 어디에 저장하느냐로 줄인다
- 숫자보다 키가 크고 값이 흩어져 있어 기본 키로 쓰면 인덱스가 커진다. 매핑 테이블은 갱신할 때만
  쓰고 행 수가 크지 않아 결정 요인은 아니다

## Discussion

- **AI 주장과 근거** — 처음에는 (나)를 권했다가, (나)가 데이터를 잃었을 때 식별자가 바뀐다는 약점이
  "한 번 발급하면 바꾸지 않는다"(ADR-0010)와 부딪힌다며 (다)로 바꿔 권했다
- **반박** — 사용자가 세 가지를 물었다. 비밀 키 계산은 성능 부담이 없나 / 식별자 유지가 DB 를 엎는
  상황까지 필요한가, 마이그레이션이 있지 않나 / 생성 로직을 바꾸거나 같은 방을 여러 개 넣을 수 없나
- **검증 결과** — 비밀 키 계산(HMAC-SHA256)은 로컬 측정에서 한 번에 약 136 나노초로 무작위 UUID(약 137)와
  같았다. 마이그레이션·백업은 발급 방식과 무관하게 저장된 값을 옮기므로, (다)의 이점은 데이터를 잃고
  처음부터 다시 만드는 사고 한 가지로 좁아졌다. 또 (다)의 "로직을 못 바꾼다"는 제약은 그 이점에 기대는
  경우에만 생기는, 이점과 같은 것의 뒷면이었다. 같은 상품을 둘로 두는 것은 (다)로는 불가능했다
- **그래서 어떻게 바뀌었나** — 드문 사고 대비가 늘 따라오는 대가(역추적 또는 키 관리, 입력 고정, 중복 불가)와
  맞지 않아 AI 추천을 (나)로 되돌렸다

## Verification

같은 공급사 코드로 다시 동기화했을 때 저장된 식별자가 유지되고 이름만 갱신되는지
  → `CatalogSyncIntegrationTest.다시 동기화해도 내부 식별자가 그대로다`

식별자를 앱이 무작위로 만드는지
  → `app/src/main/kotlin/com/stayaggregator/mapping/MappingRepository.kt` 의 `UUID.randomUUID()`
