# 0023. 연박 예약 가능 객실 수는 날짜별 잔여 수의 최솟값으로 판정

## Context

검색 응답에는 객실 타입마다 요청 기간 전체를 예약할 수 있는 객실 수를 담아야 하고, 0 이면 예약 불가다.
판정 규칙은 우리가 정한다.

두 공급사는 재고·요금 조회 응답에서 객실 타입마다 **숙박일(체크인일~체크아웃 전날)별 잔여 객실 수**만 준다.
재고는 객실 타입 단위이고 물리 객실은 드러나지 않으며, 기간 전체의 잔여 수 하나를 계산해 주지 않는다.
예를 들어 3박 검색에 날짜별 3/1/5 가 오면 이 셋에서 숫자 하나를 정해야 한다.

실제 연동 API 를 조사한 결과([연박 재고 표현 조사](../research/multi-night-inventory.md))

- 재고를 올려 보내는 방식의 API 는 우리 공급사처럼 객실 타입 × 날짜 단위로 준다
- 검색해 가는 방식의 API 는 공급사가 기간 전체를 계산해 요금마다 숫자 하나를 준다. 계산 방법은 공개돼 있지 않다
- Google 은 체크아웃 전날까지 모든 날짜가 가능해야 한다고 명시한다. 잔여 **개수**를 기간 전체로 계산하는 규칙을 적은 공식 문서는 찾지 못했다
- 실제 데이터에는 최소·최대 숙박일, 체크인·체크아웃 불가일, 판매 중지 같은 제약이 함께 오지만 우리 공급사는 주지 않는다

## Options

- **(가) 날짜별 잔여 수의 최솟값** ← AI 추천 — 3/1/5 → 1, 하루라도 0 이면 0. 날짜마다 남는 여유분은 드러나지 않는다.
- **(나) 체크인일의 잔여 수** — 3/1/5 → 3. 둘째 날 방이 없어도 예약 가능으로 보여 팔 수 없는 방을 노출한다.
- **(다) 평균이나 합계** — 3/1/5 → 3 또는 9. 기간 전체에 몇 실을 팔 수 있는지와 무관한 숫자가 된다.

## Decision

**(가)** 를 택한다. 객실 타입의 예약 가능 객실 수는 요청 숙박일별 잔여 객실 수 중 가장 작은 값으로 하고,
어느 하루라도 0 이면 0(예약 불가)이다.

**이유** — 기간 전체를 예약하려면 매일 밤 그 타입의 방이 한 실씩 있어야 하므로, 가장 적게 남은 날의 수를 넘겨 팔 수 없다.
"모든 날짜가 가능해야 한다"는 부분은 조사한 공식 문서와 맞고, 개수를 최솟값으로 잡는 부분은 공식 근거가 아니라 이 논리에서 나온 판단이다.
스펙이 주는 정보 안에서 할 수 있는 가장 작은 규칙으로 둔다.

## Consequences

**얻는 것**
- 날짜 하나라도 방이 없는 객실 타입을 예약 가능으로 보여 주지 않는다
- 공급사마다 날짜별 잔여 수만 표준 형태로 바꾸면 판정 규칙은 하나로 쓴다

**잃는 것**
- 날짜마다 다른 물리 객실을 배정해도 연박이 성립한다는 전제에 기댄다. 공급사가 연박을 같은 물리 객실로만 판다면 실제보다 많게 보일 수 있다
- 최소 숙박일, 체크인 불가일 같은 제약은 판정에 들어가지 않는다. 그런 제약을 주는 공급사가 붙으면 이 규칙만으로는 팔 수 없는 방을 노출한다

**남겨 둘 것**
- 연박 판정은 더 고민해 볼 지점으로 남긴다. 최솟값의 공식 근거, 물리 객실 전제, 제약 조건을 어느 계층에서 판정할지를 다시 볼 수 있다
- 공급사 응답의 날짜 목록이 숙박 기간과 맞지 않을 때(빠진 날, 범위 밖 날짜, 음수)는 Q24 에서 정한다

## Discussion

- **AI 주장과 근거** — 스펙상 날짜별 잔여 수만 있으니 최솟값으로 판정하자고 권했고, 약점으로 물리 객실 전제를 들었다
- **반박** — 정보를 이렇게밖에 못 얻나, 물리적으로 같은 객실인지 알 방법은 있나, 실제 현업에서는 데이터가 이것뿐이지 않을 것 같다
- **검증 결과** — 스펙에는 물리 객실을 알 방법이 없다. 공개 개발 문서를 조사하니 현업 데이터에는 제약 조건이 더 있고,
  기간 전체 판정은 "모든 날짜가 가능해야 한다"까지만 공식 문서에 있었다. 최솟값 계산과 물리 객실 전제를 직접 뒷받침하는 문장은 없었다
- **그래서 어떻게 바뀌었나** — 결정은 (가) 그대로, 이유를 "공식 규칙과 맞는 부분"과 "우리 판단인 부분"으로 나눠 적었다. 제약 조건의 부재와 재검토 여지를 남겼다

## Verification

예시 날짜별 잔여 수 3/1/5 가 1 로 판정되는지
  → `AvailabilityNormalizerTest.날짜별 요금은 세금까지 더한 총액이 되고 재고는 최솟값이 된다`

2/0/4 가 0 으로 판정되는지
  → `AvailabilityNormalizerTest.하루라도 0 이면 예약 가능 객실 수는 0 이고 응답에서 빼지 않는다`
