# 0022. JVM 툴체인을 25 로 올리기로 결정

이 ADR 은 [ADR-0007](0007-build-and-framework-versions.md) 의 JVM 타깃 부분(21)을 대체한다. Boot·Kotlin·Gradle 버전 결정은 그대로다.

## Context

[ADR-0007](0007-build-and-framework-versions.md#jvm-타깃) 은 JVM 타깃을 21 로 정했다. 이유는 이 설계가 22 이상의 API 를 쓰지 않는다는 것,
툴체인 다운로드 저장소 플러그인을 넣지 않으므로 가장 널리 깔린 LTS 여야 빌드하는 사람의 컴퓨터에 있을 확률이 높다는 것이었다.
같은 ADR 에 "가상 스레드를 도입하면 런타임을 24 이상으로 올리는 것이 이득"이라고 적어 두었고,
[ADR-0021](0021-block-on-virtual-threads.md) 에서 요청 처리를 가상 스레드로 하기로 했다.

확인한 사실

| 사실 | 원문 |
|---|---|
| `synchronized` 안에서 기다리는 가상 스레드도 플랫폼 스레드를 놓아주게 한 변경은 Java 24 에 들어갔다 | [JEP 491](https://openjdk.org/jeps/491) |
| Spring Boot 는 가상 스레드에 "Java 24 or later is strongly recommended" 라고 한다 | [Spring Boot, Virtual threads](https://docs.spring.io/spring-boot/reference/features/spring-application.html#features.spring-application.virtual-threads) |
| 22–24 는 non-LTS 로 Premier 지원이 6개월씩이라 각각 2024-09·2025-03·2025-09 에 끝났다. 셋 다 이미 끝났다. 21 LTS 는 2028-09, 25 LTS 는 2030-09 까지다 | [Oracle Java SE Support Roadmap](https://www.oracle.com/java/technologies/java-se-support-roadmap.html) 의 "22 - 24 (non-LTS) … Premier Support Until September 2024 - September 2025" |
| Boot 4.1.1 이 관리하는 Netty 4.2.17 은 Java 25 이상에서만 기본으로 `sun.misc.Unsafe` 를 쓰지 않는다. 24 에서는 Unsafe 를 계속 쓴다 | [PlatformDependent0.java L640–L649](https://github.com/netty/netty/blob/netty-4.2.17.Final/common/src/main/java/io/netty/util/internal/PlatformDependent0.java#L640-L649) · [Boot 4.1.1 의존성 목록](https://github.com/spring-projects/spring-boot/blob/v4.1.1/platform/spring-boot-dependencies/build.gradle) |
| JDK 24 는 `sun.misc.Unsafe` 메모리 접근 메서드를 처음 호출할 때 기본으로 경고를 낸다 | [JEP 498](https://openjdk.org/jeps/498) |
| Boot 4.1.1 은 Java 26 까지, Gradle 9.7.1 은 9.1.0 부터 Java 25 툴체인을, Kotlin 은 2.3.0 부터 Java 25 바이트코드를 지원한다 | [Boot System Requirements](https://docs.spring.io/spring-boot/system-requirements.html#:~:text=Spring%20Boot%204.1.1%20requires%20at%20least%20Java%2017) · [Gradle Compatibility](https://docs.gradle.org/current/userguide/compatibility.html#java_runtime) · [Kotlin 2.3.0 What's new](https://kotlinlang.org/docs/whatsnew23.html) |
| `kotlin { jvmToolchain(N) }` 은 Java 컴파일 태스크의 툴체인도 함께 바꾸고, `jvmTarget` 을 따로 정하지 않으면 툴체인 버전으로 둔다 | [Kotlin, Gradle Java toolchains support](https://kotlinlang.org/docs/gradle-configure-project.html#gradle-java-toolchains-support) |
| Gradle 은 툴체인을 컴파일·테스트·javadoc 태스크에 쓰고, `JavaExec` 의 실행 JDK 기본값도 툴체인이다 | [Gradle, Using Java toolchains](https://docs.gradle.org/current/userguide/toolchains.html#sec:using-java-toolchains) · [JavaExec javaLauncher](https://docs.gradle.org/current/dsl/org.gradle.api.tasks.JavaExec.html#org.gradle.api.tasks.JavaExec:javaLauncher) |

## Options

- **(가) 툴체인 전체를 25 로** ← AI 추천 — 컴파일·테스트·`bootRun` 이 JDK 25 하나로 돈다. 설정 한 줄이다.
  대신 컴파일 결과를 JDK 21 에서 실행할 수 없다.
- **(나) 타깃은 21, 테스트와 `bootRun` 의 실행 JDK 만 25** — 바이트코드는 21 에서도 돈다. 대신 `test`·`bootRun` 에 실행 JDK 를
  따로 지정하는 설정이 늘고, 가상 스레드 결정이 25 를 전제하므로 21 에서 돌릴 일이 없다.
- **(다) 21 유지** — ADR-0007 을 바꾸지 않는다. 대신 Boot 가 강력히 권장하는 조건을 벗어난 채 가상 스레드를 쓴다.

## Decision

**(가)** 를 택한다. `jvmToolchain(25)` 로 컴파일 JDK·타깃·테스트와 `bootRun` 실행 JDK 를 모두 25 로 둔다.
툴체인 다운로드 저장소 플러그인은 계속 넣지 않고, README 에 JDK 25 가 필요하다고 적는다.

**이유** — 가상 스레드를 쓰기로 한 이상, 24 에서 들어온 pinning 해소와 Boot 의 권장 조건을 충족해야 한다.
그중 LTS 이고 Boot 관리 Netty 가 Unsafe 경고를 피하는 첫 버전이 25 다. 21 을 골랐던 설치 확률 근거는 이 결정의 무게를 바꾸지 않는다.

## Consequences

**얻는 것**
- 가상 스레드를 Boot 가 권장하는 조건에서 쓴다
- 컴파일과 실행 JDK 가 하나라 설정이 갈라지지 않는다
- LTS 지원 기간이 21 보다 2년 길다

**잃는 것**
- 컴파일 결과를 JDK 21 에서 실행할 수 없다. "22 이상의 기능은 쓰지 않는다"는 ADR-0007 의 표시도 사라진다
- 툴체인은 Gradle 태스크에만 적용된다. 빌드한 jar 를 `java -jar` 로 직접 띄울 때는 그 명령의 JDK 가 25 여야 한다
- Netty 가 25 에서 고르는 Unsafe 없는 경로의 성능 차이는 확인하지 않았다

## Discussion

- **AI 주장과 근거** — 25 를 권하면서 가장 약한 점으로 "빌드하는 사람의 컴퓨터에 JDK 25 가 있어야 한다"를 들었다
- **반박** — JDK 25 설치는 당연한 일이고 근거에 들어갈 필요가 없다
- **검증 결과** — 요구사항은 Java 21 이상을 허용할 뿐 설치 편의를 요구하지 않는다. 설치 확률은 버전 선택의 무게를 바꾸는 사실이 아니었다
- **그래서 어떻게 바뀌었나** — 약점에서 뺐다. 기존 ADR 을 고치자는 제안이 있었으나 [ADR-0001](0001-record-decisions-as-adr.md#decision) 의
  "뒤집을 때는 새 ADR" 규칙에 따라 이 ADR 로 대체하고 ADR-0007 에는 대체 표시만 달았다

## Verification

툴체인이 25 로 선언돼 있는지
  → `app/build.gradle.kts` 와 `mock-supplier/build.gradle.kts` 의 `jvmToolchain(25)`

그 JDK 로 실제로 컴파일·실행되는지
  → `./gradlew :app:bootRun` 이 Homebrew 의 `openjdk@25` 로 돌았다(2026-09-17 프로세스 확인).
    툴체인 다운로드 저장소 플러그인은 넣지 않아, 그 JDK 가 깔려 있어야 빌드된다
