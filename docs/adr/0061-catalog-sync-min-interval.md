# 0061. 숙소 목록 갱신 주기의 최소 간격을 1시간으로 두고 설정 검사로 지키기로 결정

## Context

[ADR-0016](0016-catalog-sync-interval-default-daily.md) 이 갱신 주기를 기본 하루 한 번으로 두고 설정으로 바꿀 수 있게 했고, 허용 범위를 둘지를 넘겼다 (Q19).

목록 동기화는 공급사마다 목록 전체를 받고, 매핑 테이블을 공급사 단위 트랜잭션으로 갱신한다 ([ADR-0038](0038-catalog-sync-execution.md)).
공급사 규약은 숙소 목록이 자주 바뀌지 않는다고 적는다. 앞선 실행이 끝난 시점부터 주기를 재므로 실행이 겹치지는 않는다 ([ADR-0013](0013-catalog-sync-on-startup-and-interval.md)).

## Options

- **(가) 최소 간격을 1시간으로 두고, 더 짧으면 앱이 뜨지 않게 한다** ← 채택 — 운영자가 실수로 넣은 짧은 주기를 막는다. 대신 1시간에 측정 근거가 없다
- **(나) 최소 간격을 동기화 한 번이 걸리는 시간으로 둔다** — 설정에서 유도된다. 대신 실행이 겹치지 않아 막을 것이 거의 없고 공급사 부담은 막지 못한다
- **(다) 두지 않는다** — 운영자를 믿는다. 대신 실수를 막지 못한다

## Decision

- 갱신 주기가 **1시간보다 짧으면 앱이 뜨지 않는다**
- 이 검사는 주기 설정을 읽는 곳에서 한다

**이유**

- 목록 갱신은 공급사가 새로 올린 상품을 따라잡는 일이다. 규약이 목록은 자주 바뀌지 않는다고 하므로 분 단위로 돌릴 이유가 없다
- 짧은 주기는 목록 전체 조회로 공급사에 부담을 주고, 매 주기 공급사 단위 트랜잭션이 매핑 테이블에 쓰기를 건다
- 1시간은 기본값(하루)에서 충분히 짧고, 실수로 넣기 쉬운 초·분 단위를 막는 선이다. 측정한 값이 아니라 그 목적에서 고른 값이다

## Consequences

**얻는 것**
- 초·분 단위 주기로 잘못 뜨는 일이 없다

**잃는 것**
- **1시간에 측정 근거가 없다.** 목적에서 고른 판단값이다
- 급히 목록을 다시 받고 싶어도 주기를 1시간 아래로는 못 줄인다. 앱을 다시 띄우면 기동 직후 한 번 받는다

## Discussion

- **AI 주장과 근거** — (가)를 권했다. 근거는 규약의 "목록은 자주 바뀌지 않는다"와 공급사·DB 부담이다
- **사용자 판단** — (가)로 정했다

## Verification
